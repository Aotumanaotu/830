### 5.7 结构体、链表和文件

结构体把多个成员组合为一个对象；`s.x` 访问对象成员，`p->x` 访问指针所指对象的成员。结构体可能存在对齐填充，大小不一定等于成员大小简单相加。共用体成员共享存储空间；枚举定义命名整数常量；typedef 定义类型别名。

链表插入要先保留后继连接，例如在结点 p 后插入 s：`s->next=p->next; p->next=s;`。删除后继时要先保存待删结点、更新连接，再释放。始终说明是否有头结点、是否为循环链表。

文件常用操作：`fopen`、`fclose`、`fgetc/fputc`、`fgets/fputs`、`fscanf/fprintf`、`fread/fwrite`。打开失败返回空指针。读取循环应以读操作返回结果为依据，不用 `while(!feof(fp))` 预判“下一次必定能读”。`fgetc` 的结果先用 int 保存，以区分普通字符值与 EOF。


### S001 结构体与结构体指针

结构体把同一对象的多个属性组合成一个自定义类型。用机器人状态举例：电量是int，速度是double。

```c
struct RobotState {
    int battery;
    double speed;
};
```

这是类型定义，结尾需要分号。`struct RobotState r={80,0.5};` 创建变量r，并按成员声明顺序初始化battery和speed。`struct RobotState *p=&r;` 创建指向该结构体对象的指针p。

| 对象/表达式 | 用法 |
|---|---|
| r 是结构体变量 | `r.battery`、`r.speed` |
| p 是结构体指针 | `p->battery`、`p->speed` |
| 先解引用再访问 | `(*p).battery` 等价于 `p->battery` |

运算符 -> 由相邻的减号和大于号组成。`(*p).battery` 中括号有作用：先通过p取得结构体对象，再用点访问成员。不要将它写成 `*p.battery`。通过p修改成员会改变实际对象r的相应成员。


### P0022 结构体传参与成员赋值

C函数传参均复制实参的值：结构体形参复制整个结构体；指针形参复制地址值。前者修改局部副本，后者可通过p->成员沿地址访问原结构体。

`p->speed = 0.8`直接将成员写为0.8，不与旧值相加；`p->speed += 0.8`才在旧值基础上累加。通过指针访问原对象与采用哪一种赋值运算符，是需要分别判断的两件事。依据：本章S001成员访问，以及C08值传递与指针参数。

### P0024 指针形参自身与所指对象

指针形参自身也是独立的局部变量，复制实参地址值。`p->成员 = 值`通过当前地址修改所指对象；`p = 新地址`改的是函数内p保存的地址。之后访问p->成员时必须按新的指向判断对象，不能沿用调用时的指向。依据：C08值传递与指针参数、C09/P006修改指针形参自身。

### P0025 写完整结构体指针函数

函数参数列表中的`struct RobotState *p`不加分号；函数体内赋值语句和复合赋值语句须用分号结束。例如：

```c
void update(struct RobotState *p) {
    p->speed = 0.8;
    p->battery += 5;
}
```

### P0026 结构体数组入门

结构体数组的每个元素都是完整的结构体。`robots[0].battery`访问第0个结构体的battery成员。`struct RobotState *p = robots;`在初始化表达式中使p指向第0个元素；p++前进一个struct RobotState元素，之后p->成员访问新的当前元素。字节距离是sizeof(struct RobotState)，不等于固定1字节；不要假设结构体大小等于成员大小简单相加。

参考：[SRC-3e5aa9fedc03:p14:c0]《C语言程序设计重点笔记》第14页11.5节（结构体数组）与11.6节（指针）；[KNOW-C09]数组及按所指类型移动。此处只讲数组元素和指针访问，不宣称整个C10.02已覆盖。

### P0028 遍历结构体数组

结构体数组可用下标逐个访问。对2个元素，`for (int i=0; i<2; i++)`依次以i=0、i=1执行循环体；i变为2时条件不成立，循环结束。`robots[i].battery += 5;`每次修改当前第i个结构体的电量。对一个成员的修改不自动改变其他成员或其他元素。

数组内修改和指针成员访问遵循同一对象规则，`p=&robots[0]`后`p->speed`访问第0个结构体的speed。参考：[KNOW-C10]结构体数组与成员访问；[KNOW-C09]数组指针。只用于当前结构体数组小节，不自动覆盖C06整个循环章。

### P0029 将结构体数组传给函数

在函数参数声明中，`struct RobotState robots[]`调整为`struct RobotState *robots`，函数参数相当于结构体指针。数组作为实参时转换为首元素地址；通过`robots[i]`访问和修改调用者数组的结构体成员。元素数量由n单独传入。函数仍按值复制地址参数与整数n，C的值传递规则没有变化。

循环边界应与传入的有效元素数量对应，数组下标从0开始。参考：[KNOW-C08]数组作为函数参数；[KNOW-C10]结构体数组遍历。当前只做基础填空，不代用户写答案。

### P0031 链表结点与next

一个基础单链表结点可写为`struct Node { int data; struct Node *next; };`。data保存数据，next是指向另一Node的指针，保存后继结点地址。`a.next=&b`将a的next成员指向b；NULL表示此处没有后继，示例无头结点且不是循环链表。NULL由stddef.h等标准头文件提供。

`p->next`先访问p所指结点的next成员，结果是另一个结点地址；`p->next->data`再访问该后继结点的data。每个->都根据其左侧指针所指对象来判断成员归属。这里使用main内实际存在的结点对象，只跟踪next访问，暂不涉及动态分配、插入或删除。参考：[KNOW-C10:c0]单链表连接操作提要；[KNOW-C09]指针与所指对象。

### P0032 沿next移动

`p=p->next;`读取当前结点的后继地址，再将该地址存回p，使p指向后继结点。下一句`p->data`要按移动后的p判断当前结点。以NULL结束的单链表，尾结点的next为NULL；遍历时需要确认p非NULL后再访问成员。此例只移动到实际存在的三个结点，不对NULL解引用。依据：[KNOW-C10]链表结点连接；[KNOW-C09]改变指向与所指对象。

### P0033 单链表的完整遍历

本节head直接指首个数据结点，没有额外头结点；空链表head为NULL。遍历时，当前p不为NULL表示还有结点，先访问该结点的data，再沿next移动。走过尾结点后p变为NULL，下一轮条件不成立。while是先判断条件再执行循环体。

访问p->data之前必须确认p非NULL；以p是否存在作为访问当前结点的条件，才能处理末尾结点以及空链表。求和变量应先初始化为0，每轮累计当前data并保证指针前进。参考：[KNOW-C10]结点与next、沿next移动；[KNOW-C09]指针所指对象与NULL。当前仅练基本遍历，不宣称插入删除已学完。

### P0033遍历条件订正：当前结点与后继

累加当前结点data时，条件是`p != NULL`。`p->next != NULL`判断当前结点是否有后继，尾结点没有后继但其data仍需处理，因此会漏加尾结点。若head为NULL，计算`p->next`会访问空指针，行为未定义；先判断p非NULL即可让空链表执行0次、返回初始sum=0。此处讨论无头结点、以NULL结束的单链表遍历求和；寻找尾结点等其他任务可能使用不同条件。

### P0035结点计数与P0036指定结点后插入

结点计数复用遍历框架：count初始化0，p非NULL时count增加1并沿next移动；计数不依赖data。

在有效结点p后插入独立的新结点s（s不在原链表中）：先`s->next=p->next;`让新结点保存原后继地址，再`p->next=s;`让原结点接上新结点。两句修改next成员，不移动p或s。若p原是尾结点，第一句让s->next为NULL，s成为新尾结点。先修改p->next会覆盖原后继地址，因此应保留连接后再改接。示例无头结点、非循环链表，结点为main内实际对象，暂不涉及malloc或free。依据：[KNOW-C10]单链表插入提要、[KNOW-C09]地址与成员。

### P0037反序连接的逐句更新

初始p指a、s指独立x、a.next指b。先执行`p->next=s;`会使a.next变为x地址；此后再执行`s->next=p->next;`，右侧读取的是更新后的a.next，故x.next指向x自身。p仍指a、s仍指x。b对象并未被销毁，b.next仍为NULL，但从a沿next无法到达b；路径进入x自环，无法到达NULL。正确后插应先保留原后继再覆盖连接。尾结点后插亦如此：正确时新结点next为NULL；反序时同样产生新结点自环。

### P0039后插函数与地址传参

将后插操作封装为`void insert_after(struct Node *p, struct Node *s)`，本题约定p/s非NULL，p为已有结点，s为不在原链表中的独立新结点。指针形参复制的是地址值，仍指向调用者的实际结点；通过->修改next会修改这些结点的成员。仅重新给形参p或s赋地址则只改变局部指针本身。本题不涉及分配释放及修改首结点指针。参考：[KNOW-C10]结构体地址传参与后插连接顺序。

### P0040摘下后继并保留对象

保证p与p->next均非NULL时，可先`struct Node *q=p->next;`保存待摘下结点，再`p->next=q->next;`让前驱接到其后继。可选的`q->next=NULL;`让摘下结点不再连接原后继；q仍指该结点，p仍指原前驱。这里只改变连接：main局部结构体对象仍存在，不能对其地址调用free。动态分配结点的删除与释放另行学习；摘下、对象生存期与内存释放需要区分。依据：[KNOW-C10]单链表删除提要及[KNOW-C09]成员访问。

### P0040成员归属与剩余链表路径订正

p指a、q指b时，`p->next`是a.next，`q->next`是b.next。执行`p->next=q->next;`先将c地址写入a.next；再执行`q->next=NULL;`只清空b.next。两个next是不同对象的成员，修改一个不会自动修改另一个。从a遍历按a.next走到c，再沿c.next继续，摘下的b仍由q指向但不在从a可达的链表中。

### P0042摘下后继函数的边界与返回值

`struct Node *`返回类型表示返回一个结点地址。给定有效非NULL的p，若p->next为NULL则没有可摘下的后继，应直接返回NULL，避免随后读取空q的成员。存在后继时，用q保存其地址，更新p.next绕过q，再清空q.next并返回q；返回的是既有结点地址，不是新建局部结构体的地址。此函数不释放对象。调用者须遵守p有效的前提；p->next判断在这里用于后继操作的边界，与遍历当前结点data的p非NULL条件适用场景不同。

### P0042成员运算符的类型检查

结构体对象node的成员用`node.next`，结构体指针p的成员用`p->next`。对指针先解引用后，`(*p)`是所指结构体对象，因此`(*p).next`等价于`p->next`；括号必需。无后继的判断意图与选择正确的成员运算符需要分别检查。

### P0046无头结点链表的首指针与首插

本例head是`struct Node *`指针变量，保存首个数据结点地址；链表没有额外头结点，空链表head为NULL。对独立新结点对象x，首插先`x.next=head;`保存原首结点地址，再`head=&x;`更新首指针。x是对象因此用.，head保存地址；此操作不修改原首结点a.next。若head原为NULL，同样两句可建立只含x的链表，其next为NULL。示例操作在main内执行，结点均为有效局部对象，不涉及分配释放。

### P0047首插函数中的形参与首指针

函数`void push_front(struct Node *head, struct Node *s)`中的head是局部指针形参，传入调用者head的地址值副本。通过`s->next=head;`访问s所指实际结点并修改next；`head=s;`重赋局部形参head，不会自动重赋main中的同名指针变量。区分修改实际结点的成员与修改复制的指针变量；更新调用者首指针可用返回新首地址并赋回，或传入首指针变量地址，后续分步学习。

### P0048返回新首地址并由调用者赋回

首插函数可返回`struct Node *`：连接新结点到原首结点后，返回新结点地址。main要接收这个返回值并赋回自己的head，才会改变调用者首指针。只调用函数而丢弃返回值，main的head仍为旧地址，但新结点的next成员仍会被函数写入。函数返回地址与调用者赋值是两个动作；返回值本身不会自动覆盖实参变量。新结点为调用者提供的有效对象，不返回函数内新建局部结点地址。

### P0050二级指针访问首指针变量

head的类型为`struct Node *`，保存结点地址。`&head`是首指针变量本身的地址，类型为`struct Node **`；`struct Node **pp=&head;`使pp指向head这个变量。表达式`*pp`访问head保存的结点地址，作为赋值左侧时可修改head：`*pp=&x;`将head改为指向x，而pp仍指向head。先令x.next保存原head值再更新首指针可完成首插。后续函数若接收&head，通过解引用访问main中的head即可更新调用者首指针，仍是按值复制地址。依据：[KNOW-C09]二级指针与通过函数修改调用者指针；[KNOW-C10]首指针更新。

### P0051二级指针首插函数

函数`void push_front_ref(struct Node **headp, struct Node *s)`接收首指针变量的地址，headp必须有效地指向这个变量。`*headp`访问调用者head，值为原首结点地址；新结点先保存该地址，再通过`*headp`更新调用者head。调用时传入`&head`，无需接收函数返回值。headp形参本身仍按值复制地址，但其所指对象恰好是调用者指针变量，因此解引用赋值能修改它。空链表时*headp为NULL，这套连接仍成立。

### P0051两种首指针更新方案配套

返回指针方案：返回类型`struct Node *`，函数连接后返回s，调用者显式将返回值赋回head。二级指针方案：返回类型void，函数先令s->next保存*headp，再用`*headp=s;`直接更新main的head，调用时传&head。不能把return s;混入void方案替代更新语句；它不符合void返回声明，也不完成对调用者head的写入。

### P0053摘下首结点：更新首指针与返回摘下地址

首指针变量地址由有效headp传入，*headp表示首结点地址；为空则返回NULL。非空时q保存原首地址，把调用者首指针更新为q的后继，再清空q.next并返回q。二级指针用来修改调用者变量，返回值用来交回摘下结点地址，两者可同时存在。是否能返回地址由函数返回类型决定，并非所有二级指针函数都为void。示例局部结点仅摘下并保留对象，不释放内存。依据：[KNOW-C09]二级指针和指针返回；[KNOW-C10]摘下结点与首指针更新。


### P0081 带头结点的单链表

本节为以NULL结束的单链表。头指针head是指针变量；头结点H是额外放在数据序列前的结点，不计入数据元素。head保存&H，第一个数据结点地址为head->next。H的data字段在本例不用作数据元素；初始化为0不表示链表多一个值为0的数据元素。

空表仍保留有效H，因此head仍为&H、head->next为NULL。带头结点链表的非空/空判断与此前无头结点链表的head为NULL要按具体约定区分。随后在首部插删数据结点可通过H.next完成，通常无需改变头指针head。这里只讲带头结点模型，不改变原pop_front适用于无头结点模型的约定。

依据：[SRC-3d269b247a09:p14:c0] 朱战立《数据结构》第2章2.ppt幻灯片14（带头结点首部插删不改变头指针值）；[SRC-e798ca5196af:p6:c0]《2.3.1_单链表的定义-》PDF第6页（头结点不存数据与两种模型对照）。本例为助教原创，使用有效局部对象，不涉及分配释放。


### P0081 地址表达式与data成员订正

在head指H、H.next指a且a.data为10时，head->next是struct Node *类型，值为&a；head->next->data是int类型，值为10。若接收变量是struct Node *first，应从head取得结点地址；若接收变量是int value，则通过first访问data。用户已正确认出H和a，不把表达式多写一次->data扩大归因为认错首结点。依据：[KNOW-C10:c2225]next成员与后继data访问，[KNOW-C09:c0]指针地址与所指对象。


### P0089 带头结点链表的首插

head保存有效额外头结点H的地址，首个数据结点地址为head->next。将独立新结点x插在数据序列最前：先执行x.next=head->next;保存旧首地址，再head->next=&x;改H.next。head本身仍指H，不需改指x；空表时旧head->next为NULL，两条语句同样适用。顺序遵守一般后插规则：先保存原后继，再改前驱的next。这里只改有效局部对象连接，不分配释放。

依据：[SRC-3d269b247a09:p14:c0]第2章2.ppt幻灯片14（带头结点首部操作不改头指针）；[KNOW-C10:c3747]一般后插先保存原后继规则；[KNOW-C10:c2225]next与后继data访问。


### P0090 带头结点摘下首数据结点

本函数约定head有效指向保留的额外头结点H，不能传NULL；空表为head->next==NULL，直接返回NULL。非空时q保存首数据结点地址，head->next=q->next绕过q，q->next=NULL断开摘下结点的原后继，return q交回其地址。所有对象仍有效，不释放。

函数只写H的next成员，没有改main中head变量保存的&H，因此参数struct Node *head即可。与此前无头结点pop_front需要写回main的head不同，此处不能照搬将head改指后继的语句。首指针与头结点的next是不同的修改目标。依据：[SRC-3d269b247a09:p14:c0]带头结点首部操作不改变头指针；[KNOW-C10:c4482]摘后继与成员归属；[KNOW-C09:c831]通过地址写实际对象。示例为助教原创。


### P0092 带头结点遍历统计数据结点

head约定有效指向保留的额外头结点H，H不计入数据序列。遍历数据结点从p=head->next开始，循环条件p!=NULL；每轮计数一次，再p=p->next。空表head->next为NULL，循环0次，计数0。若从head开始则把H也遍历计数，结果比数据结点数多1；不能用头结点data是否为0来判断是否跳过。依据：[KNOW-C10:c2225]遍历当前非空结点；[SRC-e798ca5196af:p6:c0]额外头结点不存数据元素。


### P0093 带头结点链表按值查找

按值查找从head->next开始逐个比较data；head保证有效指向保留的额外头结点。当前p非NULL时才访问p->data，匹配即返回该结点地址；否则p=p->next继续。走到NULL仍未匹配，返回NULL。遇到多个相同值时，本例接口返回第一个匹配地址，return会立即结束本次函数。函数不修改next、data或调用者head。

本课find_first接口和代码为助教原创，返回类型struct Node *意味着返回结点地址，不是其整数data。概念参考：[SRC-562f320c61e1:p5:c0]《单链表的查找》PDF第5页按值查找的找到/未找到情形；[KNOW-C10:c2225]安全遍历、next与data访问。未将课件图示当作本例代码原文。


### P0093 首个匹配与return执行位置订正

在a.data=4、b.data=7、c.data=7时，查找7先比较a，再比较b；到b已满足条件，return p立即返回&b并结束函数。它不会为寻找另一个7再走到c。本次b之后的p=p->next不执行。首个匹配、最后匹配与全部匹配是不同接口；本课find_first明确返回首个匹配地址。用户返回表达式p/NULL已正确，只记录重复值返回身份错误，不编造其推理原因。


### P0095 使用查找返回的结点地址

find_first返回原结点的地址，不是复制一个结构体。调用者用struct Node *p接收后，在p!=NULL时可通过p->data修改对应原对象；找不到时返回NULL，不能访问其成员。查找函数本身不修改链表，调用者的成员写入则会改变后续查找看到的数据。再次查找应逐个读取更新后的data，不沿用上次匹配身份。只修改data不自动改变next或head。依据：[KNOW-C09:c0]通过地址写实际对象；[KNOW-C10:c2225]成员访问；[SRC-562f320c61e1:p5:c0]按值查找概念。本例接口与代码为助教原创。


### P0096 通过前驱按值摘下首个匹配结点

修改目标结点q的前驱next需要保留前驱。带头结点时pre从有效head所指H开始，while(pre->next!=NULL)保证后继存在后再比较pre->next->data。若后继匹配，q保存后继地址；pre->next=q->next绕过q，q->next=NULL断开其原后继，return q立即结束。未匹配则pre沿next前进；直到无后继返回NULL。

H不参与数据比较，其next所指首数据结点与后续目标统一按后继处理；调用者head不变。空表无后继，循环0次返回NULL。该接口只摘下现存有效对象，不释放内存。算法/代码为助教原创组合；依据：[SRC-3d269b247a09:p14:c0]带头结点首部操作；[KNOW-C10:c4482]前驱绕过与断链；[SRC-562f320c61e1:p5:c0]按值查找概念。


### P0098 摘下全部匹配结点与前驱保持

接口detach_all返回int计数，head有效指保留的头结点H。每轮检查pre的后继。匹配时保存q、pre.next绕过q、清空q.next并计数；此时pre不前进，因为它的新后继还未检查。若不匹配，才令pre=pre.next。连续匹配因此不会漏掉第二个。遍历结束后统一返回计数，不在单次摘下后立即return。

本例所有结点均为main中有效局部对象，摘下但不free；count表示摘下个数。无匹配/空表返回0。算法和接口为助教原创组合，依据：[KNOW-C10:c4482]前驱绕过与断链；[SRC-3d269b247a09:p14:c0]带头结点首部操作统一处理。
